## Project

A simple Library Book Search system. Students can search for books by title, author or subject and see book details. A librarian can add new books. This repository holds the plan for the project: user stories, acceptance criteria and the Agile board, written before any code.

## Agile Board

The board is on GitHub Projects (Board view) with five columns:

| Column | Meaning |
|---|---|
| Backlog | Work that is identified but not ready |
| Ready | Story has an owner and acceptance criteria |
| In Progress | Work has started |
| Review | Code and criteria are being checked |
| Done | All criteria are met and evidence is recorded |

Every task has one clear owner.

## Workflow

1. Write a user story in **Backlog** (draft), then convert it to an issue.
2. Add the owner, labels and acceptance criteria. Move it to **Ready**.
3. Start work and move it to **In Progress**.
4. When the work is finished, move it to **Review** and check the code and criteria.
5. Test each acceptance criterion, record the result, then move it to **Done**.

A task moves forward only when the information needed for the next stage is available.

## Definition of Done

- All acceptance criteria for the story are met.
- Each criterion has been tested and the result is recorded.
- The work has been reviewed.
- The code is committed to the repository.
- The README or issue is updated if anything changed.

## Reflection

The board showed me what was planned, in progress and done. Giving every task one owner avoids confusion, and in a team it would make collaboration easier.
